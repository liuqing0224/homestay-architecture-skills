# 阶段与交接

## 15项职责

| Skill | 核心输入 | 向下游交接 |
|---|---|---|
| homestay-arch-orchestrator | 当前任务与已有状态 | 阶段、版本、来源及实际执行记录 |
| homestay-arch-brief | 经营意向及客户需求 | 活动、客房目标、服务和投资范围 |
| homestay-arch-site | 场地与现状资料 | 可靠底图、地理/气候及到达条件 |
| homestay-arch-constraints | 地点、用途和原始依据 | 条件矩阵及待核问题 |
| homestay-arch-program | 任务书和可用范围 | 空间清单、面积平衡、邻接与楼层分配 |
| homestay-arch-massing | 场地、功能及条件 | 可比较候选、选定依据与体量 |
| homestay-arch-siteplan | 场地、功能及体量 | 建筑落位、入口、室外与专业接口 |
| homestay-arch-guestrooms | 房型目标及楼层条件 | 房型模块、逐间清单和建筑条件 |
| homestay-arch-public-spaces | 活动与峰值 | 公区布置、时段容量及服务接口 |
| homestay-arch-back-of-house | 运营任务及外包方式 | 后勤布局、物资流程和设备需求 |
| homestay-arch-circulation | 平面与各类流程 | 连续路径、冲突及专业待核点 |
| homestay-arch-sections | 地形、楼层和净高 | 关键剖面、标高与地形接口 |
| homestay-arch-envelope | 平剖、气候及材料意向 | 立面、开口、屋面与围护节点 |

| homestay-arch-delivery | 当前成果与复查证据 | 索引、版本、哈希及下阶段输入 |

## 选择与并行

资料不齐先分辨会阻断哪项决定；任务书、场地和条件可相互补充。功能面积先给方案共同基线，体量/总图与房型、公区、后勤相互迭代；动线、剖面与围护从方案期介入，协调和校审按阶段执行。不要等到“最后校审”才检查专业条件。

## 接入已有技能

- 旧 `orchestrate-homestay-design` 管整个民宿项目时，本套作为其建筑阶段；原项目状态仍是权威源。旧 `design-mountain-homestay-architecture` 可继续服务已有任务，新拆分并不自动使旧记录失效。
- `audit-architectural-drawings` 可检查已有图纸来源；本套site接收其证据清单，不把来源核对当作完整设计校审。
- 有 `interior-orchestrator` 时交接楼栋、房间、开口、轴线、标高、固定设备、材料意向和未决条件；若沿用 `design-homestay-interiors` 则交接同一组条件。长度单位转换记录到交接表。
- 有 `aia-review` 时按本次范围提供图纸、依据、问题和专业输入，审查结果带版本回传。未完成专项设计不因调用了技能而变成已通过。
- 有 `design-pm-orchestrator` 时设计费、排期、资源、管理审批和对外回执沿用其台账；本套维护设计成果及专业接口，用成果编号关联。
- 有IFC输入时先确认工具与schema/单位，按coordination检查表提取。没有解析能力时记录未执行，不用查看器截图伪造完整模型查询。

## 常见变更传播

| 上游变化 | 至少复查的下游 |
|---|---|
| 客房数量/经营服务 | 功能面积、房型、公区、后勤、交通、专业与成本 |
| 建筑入口或落位 | 总图、到达/服务路径、标高、景观、图纸及外部接口 |
| 楼层或净高 | 平剖、垂直交通、结构/机电、立面、面积和成本 |
| 开口或材料 | 客房/公区条件、立面、围护、室内、规格及成本 |
| 地形或排水条件 | 总图、剖面、挡土、结构/排水接口及施工物流 |

每次交接包含对象编号、采用的版本、来源状态、文件、检查结果及未决项。表中的复查是追踪要求，不代表工具已经自动联动。
