# 建筑体量与方案比选

先读取[共享项目约定](../homestay-arch-orchestrator/references/project-contract.md)中与本次任务相关的部分，沿用项目已有编号和权威状态；仅执行当前要求的工作。

## 输入

场地底图、功能面积、设计条件、经营任务、预算范围和客户已有选择。

## 执行

1. 按用户范围制作有实质差异的候选，通常比较两至三种；已有选定方案或只需局部深化时不强制重复比选。
2. 各方案使用相同的房间数、服务范围和面积统计口径；无法保持一致的条件单列为变量。
3. 比较建筑组合、朝向、楼层、地形响应、客房景观、公区关系、后勤及施工维护条件。
4. 先列不满足硬性条件的候选，再按有依据的功能、体验、环境、成本和实施评价比较；权重来自项目目标，不用平均分消解硬性问题。
5. 记录推荐、被舍弃原因、未决事项和客户选定依据，向总图、客房、公区、后勤和剖面移交共同几何版本。

具体核对方法见[阶段检查表](references/checklist.md)。

## 输出与验收

options/option-register.csv；各候选总图/体量/楼层关系；比选表及选定说明。

比较采用同一范围和版本；每个分值或判断有理由；效果图清楚标识方案编号和几何来源。

## 缺口与变更

关键条件不足以确定胜出方案时保留候选及其敏感条件；可继续完成不依赖选定结论的研究。
