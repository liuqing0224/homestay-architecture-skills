# 经营需求与建筑任务书

先读取[共享项目约定](../homestay-arch-orchestrator/references/project-contract.md)中与本次任务相关的部分，沿用项目已有编号和权威状态；仅执行当前要求的工作。

## 输入

客户访谈、经营设想、已确定的场地和规模、投资口径、服务范围与目标日期。

## 执行

1. 先列活动、使用者、时段和服务方式，再提出空间需求；把观景、安静、社交等意向转成可检查的设计目标。
2. 区分可售客房数、床位数、经营设定入住人数、活动峰值和员工班次；它们分别进入功能策划，不能互相替代或作为法定人数。
3. 将接待、餐饮、早餐、清洁、布草、储藏、员工和室外活动纳入范围；按业态需要取舍，记录客户选择及依据。
4. 拆清建设、装修、设备、软装、室外、顾问、税费和预备费的包含关系；有面积与可核实单价时做早期预算对照，没有单价时保留测算条件。
5. 写出固定条件、可调整条件、成果要求、范围外事项和待决问题；已有明确指令直接沿用，需要选择时说明各方案影响。

具体核对方法见[阶段检查表](references/checklist.md)。

## 输出与验收

brief/design-brief.md；brief/activity-schedule.csv（activity_id、使用者、时段、峰值、服务方式、空间需求、来源）；投资范围与决策清单。

各功能能回溯到活动；房间数、人数和预算口径明确；不把预计房价、入住率或收益写成已核实市场事实。

## 缺口与变更

缺少客群或经营方式时保留少量显式候选，先完成共同需求；不得替客户伪造选定结论。
