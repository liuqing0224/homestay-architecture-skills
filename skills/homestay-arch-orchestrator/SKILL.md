# 民宿建筑设计总控

## 建立当前项目

1. 读取项目规范、任务书、当前选定成果和已有状态。已有项目沿用其权威入口，不再创建第二套相互独立的事实源。
2. 按[共享项目约定](references/project-contract.md)记录来源、设计设定、单位、坐标、对象编号、范围及成果深度。新项目可用[状态模板](assets/project-state.md)。
3. 将当前请求定位为完整项目、阶段任务或变更。已有明确选择及授权直接使用；关键缺项只影响依赖它的结论，其他工作继续。

## 组织设计

按[阶段与交接](references/routing-and-handoffs.md)选择必要环节：经营任务书与场地、条件先行，功能面积支撑体量/总图，客房、公区、后勤、动线、剖面和围护迭代，协调及校审后形成交接成果。局部任务只加载所需技能。

使用 `homestay-arch-brief`、`site`、`constraints`、`program`、`siteplan`、`massing`、`guestrooms`、`public-spaces`、`back-of-house`、`circulation`、`sections`、`envelope`、`coordination`、`delivery` 的完整技能名。表中的阶段依赖是输入要求，不强制所有项目按固定顺序返工。

记录实际采用的技能、输入修订、输出文件、检查与待决事项。没有实际执行的环节保持未执行，不能因模板已生成而全部标为完成。

## 处理变更与衔接

- 变更以对象编号识别受影响的面积、房型、路径、图纸、模型、设备及成本，保留原版并复查新修订。
- 建筑向已有室内流程交接房间边界、开口、标高、固定设备及待核条件；项目管理与专业校审按范围接入，详见阶段与交接。
- 图纸或计算工具不存在时给出可用的方案说明及工具缺口，区分记录检查和专业设计验证。
- 本套只组织民宿建筑工作；外发、现场记录及真实审批按本次任务与实际证据执行。

## 输出

当前阶段/版本、来源与决策、成果索引、跨环节交接、问题及下一步输入。来源许可与外部方法对应见[方法来源](references/upstream-methods.md)，仅在追溯、更新或再分发时读取。
