# 建设与设计条件核验

先读取[共享项目约定](../homestay-arch-orchestrator/references/project-contract.md)中与本次任务相关的部分，沿用项目已有编号和权威状态；仅执行当前要求的工作。

## 输入

项目地点及用途、土地和既有建筑资料、规划条件、主管部门文件、委托范围、拟采用依据及来源。

## 执行

1. 明确行政地区、建筑用途、建设性质、规模和审查阶段；不能只用“民宿”名称推定其法定类别或审批路径。
2. 核实原始文件的发布机构、版本、实施和过渡条件、条款适用前提及本项目证据；按需接入已有标准核验能力。
3. 将条件写为适用对象、原文定位、设计解释、所需输入和核对方式；区分主管条件、专业要求与客户偏好。
4. 检查用地、面积口径、保留拆改、道路、设施接入、消防及无障碍等本次需要的主题；仅列线索的项目保留待核实。
5. 把会改变建筑落位、层数、房间数量或交通路径的未决条件传给方案环节，标注哪些候选可以继续研究。

具体核对方法见[阶段检查表](references/checklist.md)。

## 输出与验收

constraints/requirements.csv（condition_id、地区、来源定位、版本、适用对象、核对方法、状态）；冲突与待确认清单。

每个用于决定方案的条件有来源和适用性记录；不把GitHub示例、旧经验或异地阈值写成当前项目要求。

## 缺口与变更

来源不可取得时记录所缺证据和受影响结论；需要法律或主管认定的问题交给相应责任方，继续其他有依据的设计工作。
